# Design

## Context

See proposal.md for scope. The initial integration combined main ec9aa66 with KAN-66/KAN-67 b7a8ba1, followed by main 37441e4. The current branch reconciles main e5adc64, preserving its library-map geometry, checkpoint previews, fog reshaping, animation features and learned wall detector alongside UVTT preparation and atomic Apply/Undo. ADRs 0042 (map-token adjustment) and 0041 (UVTT) replace our earlier 0036/0037 numbers, now occupied on main. The common wall editor and owned-library geometry reuse the same optional UVTT fields; the library UVTT file-import follow-up is specified in `library-uvtt-import` and ADR 0043. Both large geometry routes retain authorized 1 MiB parsers and the global JSON limit stays 64 KiB. Review approvals remain external gates.

## Goals / Non-Goals

Publish only a complete server-validated image/grid/geometry, preserving generic portal data and exact undo. Do not infer door/window identity. Reuse the existing locking, fog-aware visibility and player portal controls; no new visibility engine or multiple scenes. Reusable library UVTT import is added by the separately scoped `library-uvtt-import` follow-up.

## Decisions

1. Pure shared UVTT schema and normalization. Supported flat formats 0.2/0.3/1.0; missing optional arrays mean empty. Strict supported data errors reject the entire file. Unknown lights/environment/extensions warn. Full image decoding belongs to a server worker; one active job, two queued, 30 second timeout. Limit input to 40 MiB, image to 25 MiB, 32 MP and 16384 pixels per edge. Raw supported geometry is additionally limited to 10000 points/items before normalization to bound processing; excessive data is rejected, never truncated. Diagnostics are twenty bounded paths/codes, never raw values.
2. Board pixels are `(point - origin) * pixels_per_grid`; grid phase is positive modulo of negative scaled origin. Preserve portal position independently of bounds and rotation in radians. Flatten adjacent polyline points, clip crop crossings, subtract collinear solid overlap at portals, then enforce 1500 walls. Grid edits change alignment without moving geometry.
3. Keep Wall.portal as the accepted `{ kind: door | window, state: open | closed | locked }`. Store optional imported position/rotation/closed/freestanding in `Wall.uvttPortal`, and source separately. Generic imports have no runtime portal designation, remain GM-only, and honor closed=false for movement; absence conservatively blocks. A GM explicitly designates a door/window through the existing tool or properties, after which runtime state controls movement and export. Reuse blocksMovement and portal.set/portal.setState/PortalChanged. GM-only wall.update records complete endpoints/metadata values. No parallel portal table or database schema.
4. Dedicated authorized REST preparation APIs use opaque revisions and existing AssetStore/room uploads. Bind drafts to GM and room, TTL 30 minutes, two unapplied drafts per pair, twenty per room owner and one hundred per process. Derive the owner from stored room ownership; legacy unowned rooms use the GM participant as quota owner. Applied receipts retain their expiry and retry behavior without consuming draft capacity. Check capacity before multipart handling and again at creation. Images needed by history remain until room deletion. Raw upload/temporary files are always removed. Restart loses preparations and requires explicit re-import.
5. Capture baseline map/grid/walls/fog in the room queue. Resolve a leased revision inside submit; stale geometry/map/grid/fog rejects, token motion does not. Apply records current token adjustment and new wall IDs from ctx.newId in one MapSet with optional wallChange and fogChange. Append failure releases the lease and retains the draft. Successful receipts make Apply idempotent. Different-image replacements explicitly clear walls/fog, and imports replace walls and clear prior fog, in the same event; historical MapSet replay never clears implicitly.
6. Undo guards map/grid/full walls/fog/affected tokens, restores exact previous values (including no map), and appends ActionUndone. Wall edits/undo use full-value equality. Player composite events cause filtered snapshots, wall updates revealing/removing/moving a visible designated portal cause filtered resyncs, otherwise are redacted; drafts/history/previous values and UVTT metadata/source never reach players; native designated portals retain ADR 0030 fog and player-control behavior.
7. Export captures a cloned filtered GM snapshot and sequence in the queue, then reads image bytes outside it. Resolve only owned library/room upload records or the built-in allowlist. PNG/WebP bytes survive unchanged; JPEG becomes PNG with identical dimensions. Format 0.3 uses origin `mod(-offset/cellSize,1)` and image size/cellSize. Fractional cell sizes fail with guidance; no resampling. Export native and imported portals, deriving closed from current runtime state when designated. Door/window identity and locks are not portable: warn in the UI and response headers, export locked as closed, and do not claim those fields in the supported round-trip guarantee.
8. Mount the 1 MiB draft JSON parser on the authorized PUT route ahead of the global 64 KiB parser. Keep Socket.IO limit unchanged. Authenticate room, active GM and live session before reading multipart. Preserve same-origin checks and limit preparation attempts to five/minute per GM/room.
9. Preserve exact JS doubles in new Postgres event payloads by inserting parameterized JSON text cast to JSONB within the current append transaction. The Prisma JSON input encoder otherwise changes some 17-digit values, invalidating checkpoint/undo guards. Keep legacy readers/schema/history and concurrent sequence-conflict behavior unchanged.

The imported draft uses the current WallSetup/WallCanvas through the existing draftConnection adapter; normal editor Save retains expectedMapUrl guards, detection result identities and atomic fog.replace. Extend draft save planning to preserve UVTT metadata/source and full endpoint edits. UVTT Apply uses its server-validated reference rather than the normal sequential wall/fog Save path. KAN-67 policy choices and adjustment-count Undo are reused.

Portal endpoint edits normalize collinear solid overlap both in private draft validation and applied wall command batches. Applied edits record affected solid removals/additions alongside WallUpdated; undo restores all exact values. Drawing skips portal gaps. Moving a portal does not reconstruct unknown solid geometry at its former opening.

## Risks / Trade-offs

- Portal `closed` has consumer-specific meanings → preserve generic metadata and test supported round trips without claiming door/window equivalence.
- Local preparations are lost on restart → explicit re-import error; no persistent scenes added.
- New persisted events cannot be read by old reducers → deploy server/web together, retain a compatible reader on rollback.
- Real-file provenance, owner review and licensed consumer/browser availability → record evidence and leave external release gates open until independently verified.
